# マクロノミカ 総合レビューレポート（2026-06）

コードベース全体（GDScript 5,010行 / データJSON 425行 / ドキュメント13本）を対象に、
①コード品質、②データ整合性、③メカニクスの実装状態、④ゲームデザイン、の4層でレビューした結果をまとめる。
指摘はすべてコード・データとの突き合わせで裏取り済み。

- 対象リビジョン: `431e127` (main)
- レビュー方法: 全コアロジック・全データJSON・全テスト・全ドキュメントの読解＋QAスクリーンショット目視
- 凡例: ★★★=致命的（中核体験を壊す） / ★★=重大（修正必須） / ★=要改善

---

## 総評

レイヤー分離（core/app/data/ui）、不変条件アサーション、JSON駆動コンテンツ、ヘッドレステスト群という**エンジニアリングの土台は優秀**。
一方で、ゲームの中核である「デッキ変質」ループが構造的に機能しておらず、データ上は存在するメカニクスの多くが
コードに配線されていない。**現状は「経済モデルのデモ」であり「ゲーム」には未達**。ただし骨抜きメカニクス・
世界デッキ汚染・非対称国家という独自性のある種は本物で、背骨の据え替えで立て直せる。

## 1. 致命的問題（★★★）

### 1-1. デッキ変質ループが死んでいる

中核ファンタジー「政策がデッキを汚染し将来の足枷になる」が、3つの実装仕様の組み合わせで無効化されている。

| 原因 | 場所 | 内容 |
|---|---|---|
| 蓄積効果が先頭5枚のみ | `src/core/world_resolver.gd:84-89` | `_sample_cards(hand + discard, 5)` は名前に反して決定的な先頭切り出し。ターン開始時手札は4枚のため、捨て札は先頭1枚しか評価されない |
| デッキが循環しない | `src/core/game_state.gd:248` | 補充は毎ターン基本1枚（`5 - hand.size()`）。初期デッキ22〜25枚は8ターンで引き切れず、`add_to_deck` されたカードはほぼ二度と手札に来ない |
| 状態カードが手札に永久残留 | `src/core/game_state.gd:263-269`, `src/core/policy_resolver.gd:99-103` | 手札を離れるのは選択政策1枚のみ。状態カードを捨てる手段がなく、監査官の除去も deck/discard しか見ない |

**帰結1（手詰まり）**: 手札5枚が全部状態カードになると政策を選べず、自動選択も政策のみ対象、
補充も0枚のため**残り全ターン恒久スタック**。回復手段なし。

**帰結2（長期投資が罠）**: 構造改革・産業政策等の見返りカード `productivity_growth` は捨て札に追加され
二度と発火しないため、「短期の痛み・長期の利益」型政策は**コスト側だけが実在しリターン側が全部死んでいる**。

**推奨**: デッキ構築の標準ループ（ターン終了時に手札全捨て＋5枚引き直し）へ変更するか、
政策をデッキから分離し常時選択メニュー化＋デッキは状態カード専用にする（→ §4-1）。

### 1-2. 配線されていないメカニクス（データに存在、コードに処理なし）

| 項目 | 場所 | 内容 |
|---|---|---|
| `administrative_drag` 死にトラック | `data/cards/vulnerabilities.json:12` | レントシーキングの効果先トラックを読むコードが**リポジトリ内に存在しない**（UI表示すらなし）。ロビイストのデメリットが二重に無効 |
| `when_commodity_shock` 未実装 | `data/cards/vulnerabilities.json:4` | 処理されるのは `when_world_demand_negative` / `when_currency_down` のみ（`world_resolver.gd:37,40`）。**C国の看板リスク「資源価格依存」が永久に発火しない**。除去政策 `resource_diversification` も無意味化 |
| `world_interest_rate` 死にトラック | `data/cards/policies.json:29,40`, `data/events/world_events.json:12,24` | 利上げ/利下げと世界イベントが書き込むが、**読むゲームロジックがゼロ**（UI表示のみ） |
| `trade_openness` 死にトラック | 同上 | 書き込みのみで読み手なし |
| ワーカー能力の未実装 | `docs/rules_v0_1.md:45-46` | 中銀スタッフ「金融ストレス上昇を抑える」、外交官「協調政策を強化する」が実装になし（全ワーカー一律コスト-1のみ） |

### 1-3. RNGの下位ビット欠陥

`src/core/rng.gd:10-16` は mod 2³¹ の線形合同法で、剰余により下位ビットを使用。
乗数・加数とも奇数のため **`next_int()` の偶奇は厳密に交互**となり、`pick()` の2要素選択・
`range_int(0,1)` は乱数として機能しない。シャッフルにも偏りが入る。
→ Godot標準 `RandomNumberGenerator`（seed指定で決定性維持可）への差し替えを推奨。

## 2. 重大問題（★★）

### 2-1. スコアリング設計の矛盾

- **世界ペナルティが順位に無影響**: `src/core/scoring.gd:13-15` の恐慌×5/金融不安×2/保護主義×2 は全国一律。
  README:29 の通り勝敗は相対順位のため、「世界を壊すコスト」が数学的にゼロ。
  バランスノートの狙い「関税は世界を悪化させる」がジレンマとして存在しない。
- **GDPギャップの線形加点**: `scoring.gd:7` の `gdp_gap * 3` は過熱（正のギャップ）を+10まで加点。
  インフレ逸脱ペナルティ（最大8点）では相殺できず、過熱戦略が割に合う。B国・D国のレガシーボーナス
  （`scoring.gd:25,29`）も `max(0, gdp_gap)` でさらに過熱を加点。
- **推奨**: 恐慌一定値で全員敗北の共倒れ条件、貿易構造に応じた国別エクスポージャー、`|gdp_gap|` ベースの評価。

### 2-2. ルール/ロジックのバグ

| 項目 | 場所 | 内容 |
|---|---|---|
| A国デッキに swap_line が2枚 | `data/modules/modules.json:3` + `src/core/deck_builder.gd:32-33` | モジュール deck_cards とハードコードの二重追加 |
| 信認容量の符号が逆（疑い濃厚） | `src/core/country_state.gd:92` | `8 - financial_stress + max(0, inflation)` — **インフレが高いほど金融政策の信認容量が上がる**。`- max(0, inflation)` の意図と思われる |
| 骨抜き政策でも圧力が満額満足 | `src/core/game_state.gd:161-168` | 圧力解決がコスト支払いの前・タグ一致のみで判定。実行不能な政策でも `if_satisfied` の実利（債務-1等）が入る |
| 「同時公開」なのに解決順固定 | `game_state.gd:165-169` | 常に国インデックス順の逐次解決。先行国の spillover が後続国のコスト容量計算に影響する非対称 |
| 空圧力デッキでクラッシュ | `src/core/country_state.gd:49` | `rng.pick()` の null を型付き Dictionary に代入 |
| ローダーの id 欠落クラッシュ | `src/data/card_loader.gd:18`, `src/data/module_loader.gd:14` | `card["id"]` を無条件参照 |
| カードID重複 | `data/cards/domestic_pressures.json:3` / `vulnerabilities.json:29` | `export_lobby_pressure` が別カードとして2定義。現状は実害なしだが index 統合で静かに上書きされる |

### 2-3. フェーズ機構のねじれ

`PHASES` の `world_event` / `domestic_update` は `_start_turn()` が `negotiation` へ直接ジャンプするため到達不能
（`game_state.gd:253`）。`resolution` も `advance_phase → resolve_turn → _start_turn` の連鎖で外部から観測不能。
UI側（`main.gd` の解決レビュー状態）が独自に補っており、ドメインとUIで二重の状態機械になっている。
→ コアのフェーズ列を実在する対話的フェーズに整理し、ターン開始処理はライフサイクルイベントとして分離。

## 3. ゲームデザイン上の構造欠陥

実装バグをすべて修正しても残る問題。詳細な議論は本レポート末尾の「設計判断が必要な論点」参照。

1. **ジャンルとスケールの矛盾**: 8ターン×初期デッキ22〜25枚では、手札全捨て制にしてもデッキは約1.7周しか回らず、
   デッキ変質を体感できない。デッキ構築は周回数を要求し、マクロ経済シムは少数の重いターンを要求する——この矛盾の解消が最優先の設計判断。
2. **フィードバックが全部「下り坂」**: デフレスパイラル・恐慌圧迫・通貨安→債務など負の複利のみで、
   正のエンジン構築要素がほぼない。競争ゲームで自国だけ崩壊を遅延させる体験は楽しくない。
3. **交渉の構造がない**: 交渉フェーズの AGENDA は UI 表示のみ（`main.gd:33,650`）。拘束力ある合意・破約コスト・
   取引材料がゼロで、協調は「偶然の同時選択」でしか起きない。
4. **1ターンの実質的決定が1個**: 政策1枚＋自明解のワーカー。ゲーム全体で実質8回の決断は薄すぎる。
5. **ワーカー配置に意思決定がない**: 競合も希少性もなく最適解が機械的（政策のコスト型に一致する割引）。
   監査官は割引なし＋汚染無害化により常に支配される選択肢。
6. **国家バランスの未検証な非対称**: A国は構造的に最強に見え、B国は開幕デフレスパイラル圏＋唯一の
   `exporter` タグで関税系 spillover の単独の的、D国は開幕の国際コスト容量0。レガシーボーナス（5〜10点）では補正不足の可能性大。
7. **可読性（霧の中のレバー問題）**: 15トラックが±1刻みで動き、解決は文章ログの羅列。
   プレイヤーが選択→結果の因果を追えず、政策選択が学習可能な技術にならない。
8. **アークがない**: 8回同質なターンの後に突然終了。中間評価・エスカレーション・最終盤の特別ルールが皆無。

### コスト体系の補足
6種の政策コストのうち実際に消費されるのは政治資本と債務のみ（`country_state.gd:58-82`）。
行政・信認・国際・産業はトラック由来の静的しきい値で、行政容量は政治資本+1（同:90）と実質重複。
「6種のコストをやりくりする」という売りの大半がリソース管理になっていない。

## 4. 推奨ロードマップ

### Phase 1: 中核ループの蘇生（最優先）
1. **政策デッキの廃止を検討**: 政策は常時選択メニュー（クールダウン制）、デッキは状態カード専用とし
   毎ターン2枚公開。これで §1-1 の手詰まり・周回不足・長期投資の罠が一挙に解消し、
   「デッキ＝国家の体質」のテーマも純化される。デッキ制を維持する場合は手札全捨て＋5枚引き直し＋ターン数延長。
2. swap_line 二重投入の修正（循環が機能し始めると実害化）
3. `administrative_drag` / `when_commodity_shock` / `world_interest_rate` の配線（実装 or データ修正）

### Phase 2: 数行で済む修正
4. RNG差し替え（`RandomNumberGenerator` + seed）
5. `draw_pressure` の null ガード、ローダーの id 欠落ガード
6. 信認容量の符号確認・修正（`country_state.gd:92`）
7. `export_lobby_pressure` のリネーム

### Phase 3: 設計判断が必要な論点（docs に決定を書いてから実装）
8. 共倒れエンド（恐慌一定値で全員敗北）→ 中心ジレンマの復活に最も安価
9. 交渉への「共同宣言」導入（コミット→違約で政治資本ペナルティ＋公開）
10. gdp_gap スコアの非線形化、世界ペナルティの国別エクスポージャー化
11. 解決順のスナップショット化 or ローテーション
12. トラック削減（為替/経常収支の統合、死にトラックの削除 or 実装）と解決演出の因果可視化
13. クライシス段階制（恐慌トラックでイベント強度がエスカレート）によるゲームアーク形成

### Phase 4: 基盤整備
14. CI追加（GitHub Actions: Linux headless Godot + `validate_data.py` + `check_godot.ps1` 相当の12テスト）
15. `validate_data.py` 強化: ファイル横断ID一意性、deck_cards の型チェック、effects 構造検証、
    **効果キー・条件キーが実装に存在するかの検証**（§1-2 の再発防止に最重要）
16. `PolicyRecommender` をAIプレイヤーにしたモンテカルロ（数百ゲーム）で国家別勝率を実測
17. 推奨AIに支払能力評価を追加（`_preview_policy_cost` 流用）、監査官推薦の追加
18. `main.gd`（1,542行）の分割: 構築/リフレッシュ/アニメーションの分離。
    未使用コンポーネント群（CountryMat 等 — main.gd から参照ゼロ）の採用 or 削除の決断

## 5. コード品質・UIの個別指摘（要改善 ★）

- `GameState.log` が組み込み `log()` を隠蔽 → `resolution_log` 等へ改名
- `preview_resolution_outcome` の `mutation_count` は変化ゾーン数であり名前と不一致
- `country_state.gd:96` の `unemployment / 2` は整数除算（警告対象）。意図なら明示
- `get_children()` 反復中の `queue_free()`（`country_mat.gd:83-85` ほか）、Tween 多重生成ガードなし
- ログ文章がドメイン層（resolver 群）に直書き → 構造化イベントを返しUI側で文章化（国際化の布石）
- `check_godot.ps1` のテスト列挙が2回コピペ → 配列＋ループ化
- `simulate_balance.py` はコスト・骨抜き・フィードバック・イベントを未モデル化でバランス検証には不十分
- `docs/card_schema.md` に `spillovers` / `mutations.add_world_card` / `remove_from_deck` / 条件付き効果キーの記載なし
- UI目視（QAスクリーンショット）: 盤面レイアウトとトークン整列は良好。一方、タイトル/国選択/ターンニュース/
  最終スコアの各オーバーレイは存在感が薄く（特に最終スコアはクライマックスとして演出不足）、
  右ペインのログ文字は実寸でも可読性が厳しい

## 6. 残すべき良い種

1. **コストベクトルと骨抜き**: 「政策は経済効果だけでは成立しない」をルール1個で表現する独自メカニクス
2. **世界デッキ汚染**: 関税→報復関税の内生的な罰。エスカレーション装置としてゲームアークの軸に拡張可能
3. **非対称国家×公共選択圧力**: 「自国の構造が自国の政治を縛る」ファンタジー
4. **エンジニアリング規律**: レイヤー分離・DbC・ヘッドレステスト・データ検証の習慣はこの規模で出色

土台は本物。背骨（ターン構造と相互作用）を据え替えれば、テストプレイで語れる段階に入る。
